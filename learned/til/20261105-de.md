# DataOps vs DevOps?
What's the difference and scope between those two?

I often find that the difference between those two is that the DataOps scope around data engineering life cycle, automation data quality check, pipeline reliablity, adapting from devops. While DevOps focusing software engineering lifecycle such as on the code development, test, build, and deployment. 

I used to think data engineers only focus on DataOps, not DevOps. It turns out DataOps builds on DevOps rather than replacing it.

Lets say you use Great Expectations, a library for asserting data quality. You write the checks as code in your job or pipeline files. That code is reviewed, tested, and deployed using DevOps principles. Then, every time the pipeline runs, those checks validate the incoming data. That part is DataOps.

I think this is what I lack, a data quality checks. I often rely too much on the code, writing only unit tests and relying on CI to verify it. In real-world scenarios, the data comes from upstream sources I don't control, and bad data can arrive even when the code is correct. That is outside what unit tests can cover since it's already deployed.
